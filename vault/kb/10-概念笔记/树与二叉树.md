# 树与二叉树

依据：第 5 章课件 p1–91（树与森林概念、二叉树性质、类定义、遍历、线索化）。树与森林、堆、Huffman 见后续笔记。

## 树

**递归定义**：`T = Φ`（n=0）；否则 `T = {r, T₁, …, Tₘ}`，r 为根，各 Tᵢ 互不相交且各自是树。

**推论（后续性质的来源）**：除根外每个结点恰有一个直接前驱 ⇒ n 个结点有 n−1 条边，且所有结点度之和 = n−1。

| 对照 | 基准 |
|---|---|
| 结点的度 / 树的度 | 度＝子女个数；树的度＝各结点度的最大值。叶的度为 0 |
| 深度 / 高度 | 深度：根为第 1 层向下数；高度：叶为 1 向上数。同一棵树数值同为 4，但基准相反，换题时容易错位 |

**ADT 的抽象点**：`Tree` 只规定 `FirstChild`/`NextSibling`/`Parent` 的语义和 `position 0` 表示空，存储方式留给实现（`position` 可为下标或指针）。枚举子女的通用写法：

```cpp
for (position c = t.FirstChild(p); c != 0; c = t.NextSibling(c)) visit(c);
```

选 `FirstChild + NextSibling` 而不是「第 i 个子女」，是因为它同时适配任意度的树，并且与第 6 段子女-兄弟表示和二叉树一一对应。

## 二叉树

**定义**：每个结点至多两棵子树，且**左右有序**；单分支时也要区分是左还是右。它不是“度 ≤ 2 的树”的简单特例。

**5 条性质**

1. 第 i 层至多 `2^(i-1)` 个结点。
2. 深度 k 至多 `2^k - 1`。
3. `n0 = n2 + 1`。推导：`n = n0+n1+n2`，`n-1 = n1+2n2`，两式相减。
4. n 个结点的完全二叉树深度 `= ⌊log₂n⌋ + 1`。
5. 1-based 编号：双亲 `⌊i/2⌋`，左 `2i`，右 `2i+1`；0-based 编号：双亲 `⌊(i-1)/2⌋`，左 `2i+1`，右 `2i+2`。

**满 / 完全**：满＝每层都满；完全＝前 k−1 层满、最后一层从左到右连续（编号 1..n 无空洞）。

**表示与判据**

| 表示 | 优点 | 代价 / 判据 |
|---|---|---|
| 顺序（数组） | 下标即父子关系，省指针 | 只对完全二叉树不浪费；右单支深度 k 需 `2^k-1` 个槽存 k 个结点 |
| 二叉链表 | 通用，插入删除不搬移 | 2n 个指针中只有 n−1 条边，必有 `n+1` 个空指针（线索化的入口） |
| 三叉链表 | 多 `parent`，向上找双亲 O(1) | 每结点多一个指针 |

## 类结构与辅助操作

- 公有函数是**包装器**，把 `root` 传给 protected 同名递归辅助函数；判空的判断因此可以只写在公有层（`Parent` 在 `root == NULL || root == t` 时直接返回 NULL）。
- `RefValue` 是**输入哨兵**，不是数据：建树时读到它就置 `subTree = NULL` 结束递归，所以它必须取数据集合之外的值。
- `destroy` 用后序遍历释放：先析构左右子树再 `delete` 根，否则子结点地址丢失。
- `Size`/`Height` 都是后序递推：`1+Size(left)+Size(right)`、`1+max(H(left),H(right))`，空树返回 0。

## 遍历

框架：V＝访问根，L＝遍历左子树，R＝遍历右子树。六种次序中课程覆盖 VLR、LVR、LRV。

| 次序 | 访问根的时刻 |
|---|---|
| 前序 VLR | 第一次到达结点 |
| 中序 LVR | 左子树遍历完成时 |
| 后序 LRV | 左右子树都完成时 |

**非递归实现与“三个时刻”一一对应**

- 前序：访问后把右子女压栈、沿左子女下行；左空则弹栈（课件用 `Push(NULL)` 作哨兵）。
- 中序：一路压左子女直到空 → 弹栈访问 → 转向右子女，循环条件 `p != NULL || !S.IsEmpty()`。
- 后序：栈元素带 `tag(L/R)`。`L` 表示从左子树返回，改标 `R` 后转右子树；`R` 表示从右子树返回，此时才访问。等价写法是「任务栈 + output 标记」逆序压入（根输出、右、左）。

**层次遍历**：用队列。出队访问，左、右子女依次入队；上一层出队正好把下一层排在队头。不用栈。

**唯一性**：前序+中序能唯一确定树（前序首元为根，在中序中切出左右长度后递归）；**前序+后序不能**——结点只有一个子女时分不清它在左还是右，例如前序 `AB`、后序 `BA` 对应两种树。

## 线索化二叉树

**动机**：遍历把结点排成线性序列，但每次找前驱/后继都要重新遍历。线索化把这种前后关系预先存进树本身，使找后继 O(1)、整树中序遍历 O(n) 且不用栈。

**空间来源**：n 个结点的二叉链表有 `n+1` 个空指针，正好够存全部前驱/后继，只额外增加两个标志位：`ltag/rtag = 0` 表示指针指向子女，`=1` 表示是前驱/后继线索。

**中序线索化的两个建立时机（最容易写错的地方）**

```cpp
createInThread(current, pre) {
  if (!current) return;
  createInThread(current->leftChild, pre);          // 先左子树
  if (!current->leftChild) { current->leftChild = pre; current->ltag = 1; }   // 前驱：当场就能填
  if (pre && !pre->rightChild) { pre->rightChild = current; pre->rtag = 1; }  // 后继：回填给 pre
  pre = current;
  createInThread(current->rightChild, pre);         // 再右子树
}
```

- 前驱线索在访问本结点时建立（左边空了，pre 就是前驱）。
- 后继线索必须推迟到访问**下一个**结点时才回填给 pre——中序里 current 的后继此刻还不知道是谁。
- 包装层在递归后补 `pre->rightChild = NULL; pre->rtag = 1;`，给中序最后一个结点收尾；空树靠 `root != NULL` 判断避开。

**求中序前驱/后继**

| 操作 | 条件 | 结果 |
|---|---|---|
| 后继 | `rtag == 1` | `rightChild`（线索） |
| | `rtag == 0` | 右子树中序第一个结点：一路 `leftChild` 且 `ltag == 0` 到底 |
| 前驱 | `ltag == 1` | `leftChild`（线索） |
| | `ltag == 0` | 左子树中序最后一个结点：一路 `rightChild` 且 `rtag == 0` 到底 |

中序首结点由 `First`（根一路向左到底）给出，末结点的 `rtag = 1` 且 `rightChild = NULL` 天然充当“无后继”的终止条件。

**前序与后序线索为什么更难**

- 前序：`ltag == 0` 时后继就是左子女；`ltag == 1`（左为空或已是前驱线索）时后继是 `rightChild`，若 `rtag == 1` 且 `rightChild == NULL` 则无后继。
- 后序：后继不一定是右子树——右子树遍历完才轮到根，所以必须回到双亲。判据是 `parent`：`rtag == 1` 取线索；否则若 p 是双亲的右子女或双亲 `rtag == 1`，后继就是双亲；否则是双亲的右子女。这正是 `ThreadTree` 需要 `parent(t)` 的原因。

## 易错点

- 深度与高度的基准互反（根/叶为 1）。
- 1-based 公式直接套 0-based 数组。
- `Height(空) = 0` 的约定必须与题给约定一致；把 `1+H(left)+H(right)` 写成高度会变成求结点数（课件 p67 第 4 题的陷阱）。
- 只有 `n+1` 个空指针这个计数结论，才能解释线索化为什么不增加空间。
- 线索树里 **指针非空 ≠ 有孩子**：找最左结点必须用 `p->ltag == 0` 作继续条件，写成 `p->leftChild != NULL` 会顺着前驱线索走回已访问结点（课件 p90–91 第 2 题）。
